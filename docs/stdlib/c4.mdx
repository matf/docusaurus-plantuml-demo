# C4 diagrams

[C4-PlantUML](https://github.com/plantuml-stdlib/C4-PlantUML) ships with the plugin. Write the
include and the diagram renders — no configuration, no separate download to arrange, and the
library is served from this site's own origin like everything else here.

````markdown
```plantuml
@startuml
!include <C4/C4_Container>

Person(user, "Reader")
Container(browser, "Browser", "JavaScript")
Rel(user, browser, "Opens a page")
@enduml
```
````

Only the namespaces a page actually includes are fetched. This page costs 29 KB gzipped for
C4; a page without a standard library include costs nothing at all.

## Level 1 — system context

```plantuml title="System context"
@startuml
!include <C4/C4_Context>

title System context for a documentation site

Person(reader, "Reader", "Wants to understand the system")
Person(author, "Author", "Writes Markdown with diagrams")

System(site, "Documentation site", "Static Docusaurus site. Renders every diagram in the reader's browser.")
System_Ext(git, "Git host", "Stores the Markdown and serves the built site")
System_Ext(ci, "CI", "Builds the site on every push")

Rel(author, git, "Pushes Markdown", "git")
Rel(git, ci, "Triggers a build", "webhook")
Rel(ci, site, "Publishes")
Rel(reader, site, "Reads", "HTTPS")

SHOW_LEGEND()
@enduml
```

## Level 2 — containers

```plantuml title="Containers"
@startuml
!include <C4/C4_Container>

title Containers inside the documentation site

Person(reader, "Reader")

System_Boundary(site, "Documentation site") {
  Container(pages, "Static pages", "HTML, CSS", "Prerendered by Docusaurus at build time")
  Container(plugin, "Diagram plugin", "React, TypeScript", "Replaces code fences with rendered SVG")
  Container(engine, "PlantUML engine", "JavaScript, ~6.8 MB", "The official engine compiled to JavaScript")
  Container(stdlib, "Standard library", "JavaScript bundles", "One per namespace, fetched on demand")
  ContainerDb(cache, "Render cache", "Memory or sessionStorage", "Keyed by source, colour mode and engine version")
}

Rel(reader, pages, "Opens", "HTTPS")
Rel(pages, plugin, "Mounts")
Rel(plugin, cache, "Reads and writes")
Rel(plugin, engine, "Loads once per page", "HTTPS")
Rel(plugin, stdlib, "Loads what the diagram includes", "HTTPS")
Rel(engine, stdlib, "Resolves !include against")

SHOW_LEGEND()
@enduml
```

## Level 3 — components

```plantuml title="Components of the plugin"
@startuml
!include <C4/C4_Component>

title Components inside the diagram plugin

Container_Boundary(plugin, "Diagram plugin") {
  Component(wrapper, "Code block wrapper", "React", "Decides whether a fence is a diagram")
  Component(component, "Diagram component", "React", "Owns state, lazy loading, zoom and the source view")
  Component(loader, "Asset loader", "TypeScript", "Injects the engine and standard library bundles once per page")
  Component(renderer, "Renderer", "TypeScript", "Serializes renders and inspects the result")
  Component(sanitizer, "Sanitizer", "DOMPurify", "Cleans the SVG before it reaches the DOM")
}

Rel(wrapper, component, "Renders for a diagram fence")
Rel(component, renderer, "Requests an SVG")
Rel(renderer, loader, "Awaits the engine and the namespaces")
Rel(renderer, sanitizer, "Passes the rendered SVG through")

SHOW_LEGEND()
@enduml
```

## Dynamic diagram

`C4_Dynamic` numbers the interactions in order rather than laying out structure.

```plantuml title="Rendering one diagram"
@startuml
!include <C4/C4_Dynamic>

title What happens when a diagram scrolls into view

Person(reader, "Reader")
Container(component, "Diagram component", "React")
ContainerDb(cache, "Render cache", "Memory")
Container(loader, "Asset loader", "TypeScript")
Container(engine, "PlantUML engine", "JavaScript")

Rel(reader, component, "Scrolls the diagram near the viewport")
Rel(component, cache, "Looks the source up")
Rel(component, loader, "Asks for the engine and any namespaces")
Rel(loader, engine, "Fetches once per page")
Rel(component, engine, "Renders to a string")
Rel(component, cache, "Stores the SVG")
@enduml
```

## Deployment diagram

```plantuml title="Deployment"
@startuml
!include <C4/C4_Deployment>

title Where the pieces run

Deployment_Node(reader, "Reader's device", "Any OS") {
  Deployment_Node(browser, "Browser", "Chrome, Firefox, Safari") {
    Container(page, "Rendered page", "HTML and JavaScript")
    Container(engine, "PlantUML engine", "JavaScript", "Runs entirely on this machine")
  }
}

Deployment_Node(host, "Static host", "GitHub Pages") {
  Deployment_Node(cdn, "Edge cache", "HTTP") {
    Container(assets, "Site assets", "HTML, JS, diagram bundles")
  }
}

Rel(page, assets, "Fetches", "HTTPS")
Rel(engine, assets, "Fetches namespace bundles", "HTTPS")
@enduml
```

## Both spellings of the include

C4-PlantUML's own documentation writes the include with the `.puml` extension. Both forms
resolve here, which is not true of the standard library bundles published upstream.

```plantuml title="Include written with the file extension"
@startuml
!include <C4/C4_Container.puml>

Person(reader, "Reader")
Container(app, "Application", "Any language")
Rel(reader, app, "Uses")
@enduml
```

## Zoom, dark mode and the source view still apply

Nothing about the standard library is special. These diagrams zoom, follow the site's colour
mode, and expose their source through the `</>` control like every other diagram on this site —
try the toolbar on the container diagram above.
